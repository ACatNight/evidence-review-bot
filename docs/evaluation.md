# 回放、审计与价值验证

状态：设计与试验计划，2026-10-01。没有已取得的性能、准确率或竞品胜出结论。

## 1. 可验证证据的边界

证据验证检查来源位置是否存在、内容摘要是否匹配、推导工具及输入是否记录、结论是否引用真实证据。代码位置真实并不能证明风险一定发生；还需检查规则前提、调用上下文和反例。向审查者展示的解释应是简洁的事实、依据与限制，不要求模型公开内部思维过程。

逐行输出应能从 finding_id 追到 run_id、固定源码位置、规则/配置/工具版本、必要公告快照、覆盖状态与发布决策。证据不足时保留诊断或候选，不能补写似是而非的事实。抑制与未发布原因对有权限的维护者可查，否则无法解释“为什么这次没评论”。

## 2. 回放分成三种操作

| 操作 | 需要的输入 | 可承诺的结果 |
| --- | --- | --- |
| 查看历史证据与审计 | 留存的脱敏结果、元数据、发布记录 | 重建当时系统记录的判断和操作，不证明未保留的原文 |
| 重新执行确定性分析 | 相同源码快照、规则/解析器/配置版本、公告响应或快照 | 对规范化 Finding、位置、Coverage 做结果比较；不比较时间戳和随机运行 ID |
| 重新调用模型 | 可用的脱敏输入及模型配置 | 新的一次模型实验，不承诺复现旧结果；只记录可合法留存的模型元数据和响应 |

回放默认不调用平台写接口，不创建 outbox 评论意图。发布记录只展示或对账；如需修复发布，走独立且有权限校验的操作。源码、公告或旧工具版本缺失时返回 `unavailable` 和具体缺失项；这是回放请求状态，不改变原 review_run 的历史终态。旧输入不可用时，用当前输入重新分析必须建立新运行并标注差异。

首版不长期保存源码。API/CLI 的回放能力需遵守当前仓库授权；权限被撤销后不得凭历史 run_id 绕过访问控制读取代码。Secret 原文不为回放而留存，脱敏结果也不作源码替代。

M1 验收：同一合成夹具或有权限的固定历史 PR 运行两次，比较规范化结果；再演示输入缺失、规则版本变化、partial 覆盖、平台写请求数为零。规则版本变化属于结果对比，不能算原运行精确重放。

## 3. 审计的可操作入口

管理员或授权维护者可按 run_id 查看/导出时间线：接收事件、快照、规则运行、覆盖缺口、过滤/抑制理由、发布尝试、平台对象 ID、反馈及配置变更。初版提供受保护 CLI/API，PR Check 至少给出 run_id、证据摘要和实际可用的访问说明。不能放一个尚未实现的“查看详情”链接。

审计采用附加记录与数据库访问控制；这不等于密码学防篡改证明。签名归档和更强存证不属于首版。通过重复投递、租约失效、发布超时等故障样例确认：维护者能解释最终是否发出了评论，以及为何重试或停止。

## 4. 对照试验

先选择同一团队正在使用的一个基线流程，不要求同时安装所有竞品。Gitee 原生只能在可获得授权的相应平台场景下实测；无法同环境比较时只做能力资料对照，不发布准确率排行榜。

固定 PR SHA、规则范围、模型/工具版本、配置和数据源时间。分别保存基线输出与本产品输出，隐藏工具名称、随机展示顺序，由两名审查者独立判断“真实且有用、真实但不值得评论、误报、证据不足”，分歧人工裁决。接受风险作为处置维度单独记录，不自动当作误报；未回复不等于采纳。

检测能力不同的产品分两层比较：共同覆盖的问题类型比较准确率和漏报；完整使用流程比较有用发现、无用评论、时间和总成本。产品未支持的类别不能从整体效果中悄悄剔除，也不能用共同范围上的结果宣称全面优于另一产品。

| 指标 | 用途与限制 |
| --- | --- |
| 有用发现数与召回率 | 必须有人工标注的检测范围；不能通过少报一切获得表面低噪声 |
| 无用评论数/PR、重复评论数 | 同时报告真实但不值得评论与误报，不只统计语法正确的评论 |
| 评论精确率 | 用同一候选/发布集合计算，报告样本量和区间；shadow 与正式发布分开 |
| 人工核查时间 | 从阅读到判断记录时间，并随机化评估顺序以减轻学习效应 |
| 证据有效率与回放结果 | 来源、版本、归因、输入可用性分别报告；缺失输入不能从分母隐藏 |
| 成本与时延 | 含部署维护、人工配置、模型、API 等成本；不能只比较 token |

沿用产品文档的初始样本计划和规则发布门槛。开始前由试点约定有用发现的可接受变化、无用评论下降目标和维护成本上限；结束后同时报告收益和损失。先按仓库/时间拆分校准集和留出评估集，避免同一 PR 的重复提交落入两边。自然 PR 与合成反例分别报告，不能混合包装成真实效果。

## 5. 反馈与校准闭环

反馈记录标注者、权限、时间、规则版本、标签和理由；经裁决的样本进入版本化 Review Dataset。默认保留在部署方，不跨租户共享，不自动用于模型训练。私有代码抽成回归夹具前脱敏或改为合成最小示例。

规则维护者在校准集提出规则或发布阈值变更，生成新版本，通过回归集和留出集比较后人工决定是否启用。记录相较旧版本哪些 Finding 增加、消失或改判，并提供回退版本。团队手册可以产生候选规范，需经过适用范围、反例和人工批准，才能变成确定性规则或模型上下文配置。

M1 提供反馈录入和导出，M2 开始版本对比与标注评估，LLM 校准随语义实验推进。首版不建设自动训练平台，也不把收集数据量当成质量优势。

## 6. 继续投入的条件

若现有工具流程已满足用户，且本产品只增加部署、权限和维护成本，应收窄为可复用的证据导出/结果筛选组件，或重新选择试点问题。如果只有 Secret 技术闭环跑通，还不能证明市场需求或产品差异成立。下一阶段投入依据是可复核的试点结果与用户继续使用意愿。
