# SEC-001 候选检测器：当前实现边界

状态：已接入 GitHub PR 快照和 Check 汇总，仍属测试仓库阶段。规则版本在 `src/rules/secret.ts` 中定义；尚未完成标注样本准确率评估，不能把它称为完整 Secret 扫描能力。

## 当前支持

- GitHub 经典令牌格式 `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_` 加 36 个字母或数字字符。命中只说明格式相符，不验证令牌有效性。
- GitHub fine-grained personal access token 格式 `github_pat_` 加 82 个字母、数字或下划线字符。仅匹配完整长度；命中不验证令牌有效性。
- 简单 PEM 私钥块：开始和结束类型一致，主体至少两行、每行 16–76 个 Base64 字符。包括普通、RSA、EC、OPENSSH 和 ENCRYPTED PRIVATE KEY 标签。带额外头字段、不同换行格式或其他编码可能漏报。
- 对 base 与 head 的同一候选做租户 HMAC 比较，忽略已有或纯移动的相同值。仅候选覆盖本次 head 变更行时报告。
- 扫描结果只返回类型、行区间、脱敏提示和租户 HMAC 指纹；输入文本与原值不作为结果返回。输入超过调用方指定上限时返回 partial。Worker 读取最多 50 个 PR 文件，每个文本文件最多 256 KB，并在 Check 中标明覆盖缺口。

## 尚未支持

其他平台/云服务密钥、低熵密码、变量名启发、熵检测、真实密钥验证、复杂 PEM 变体，以及从 diff 自动提取变更行和上下文。当前扫描器没有排除测试样例或假值的完整策略，因此候选不能直接发布为高置信评论。

调用方负责限定读取范围、使用可信 base 和固定 SHA、传入正确的变更行、保护 HMAC 密钥，并在文件读取失败或 diff 不完整时记录覆盖缺口。扫描器返回 complete 只表示当前支持格式在该输入内处理完成，不表示整个 PR 没有凭据。

进入真实发布前，按[规则契约](rules.md)补齐反例、格式清单与变更归因；和成熟检测器在同一批标注 PR 上比较精确率、漏报、性能、脱敏及许可证。检测器选择应记录到[决策记录](decisions.md)。
