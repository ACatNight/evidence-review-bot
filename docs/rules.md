# 规则契约与首版候选规则

状态：设计提案，尚无规则实现。规则 ID 沿用原始方案，语言范围和启用策略按试点收窄。

## 通用执行契约

规则输入包含不可变 ReviewSnapshot、经过可信策略过滤的文件内容、变更行映射、规则配置与版本，以及适用时的公告快照。规则不直接调用平台 API，不负责评论，也不自行读取宿主文件或任意网络地址。

规则返回候选 Findings、Evidence 引用、覆盖记录和诊断。仅有空 Findings 不能证明规则成功：必须同时返回 `complete / partial / skipped / failed` 之一，以及缺失或跳过的原因。

`severity` 表达潜在影响；`confidence` 表达当前规则及证据对判断的支持程度；`method` 标识 deterministic、hybrid 或 llm。发布策略独立决定是否展示，禁止从严重程度直接推导置信度。

每条规则声明：ID、版本、支持语言/文件格式、默认启用状态、输入需求、资源上限、配置 schema、输出类型及已知限制。规则版本变化进入分析身份，不修改旧运行的事实记录。

## SEC-001：高精度 Secret 候选

首个闭环仅覆盖明确格式的凭据和私钥特征，优先评估成熟检测器并固定其版本。变量名含 password、字符串高熵等弱线索不足以单独生成高置信度公开评论。

检测范围为 PR 新引入的凭据：读取必要完整上下文，但对 base/merge-base 与 head 做比较，区分新增、移动、复制和原有内容。多行私钥不能只扫描新增行碎片。具体支持格式必须列入实现后的规则清单，未支持格式不能被描述为已覆盖。

不对检测到的凭据调用真实服务验证有效性。Finding 说明“符合某类凭据格式”，不声称“已验证可登录”。样例、占位符和测试文件应纳入反例集；路径位于 tests 中并不足以自动证明安全。

所有输出只含脱敏片段、位置、格式类型和检测依据。需要相关性标识时使用租户范围的 HMAC，记录密钥版本并限制访问，不保存低熵密码的裸哈希。外部检测器输出必须在落盘或日志前经过脱敏。

修复建议包含：核实是否真实凭据、如真实则撤销或轮换、移出源码并改用受控 Secret 存储。单纯删除当前行不能使已暴露凭据失效。

## DEP-001：锁文件中的已知漏洞依赖

试点支持 npm 的一种经过验证的 package-lock 格式；实现时明确版本支持表。读取锁定的包名、精确版本和依赖路径，包括受支持范围内的传递依赖。仅有 package.json 中版本范围时不猜测实际安装版本。

规则职责是解析受支持锁文件、调用 AdvisorySource、使用生态兼容版本匹配库、记录关联证据。通用依赖解析和深度 SCA 继续由成熟工具承担；首版不执行 npm install、生命周期脚本或仓库代码。

对 base 与 head 使用同一公告快照比较。默认报告本次 PR 新引入的受影响依赖或升级后进入受影响范围的依赖；已有且未变化的漏洞作为背景信息，不反复新增行评论。公告更新后对未变代码的重新扫描标注“公告更新触发”，不得归咎于本次代码修改。

Evidence 包含生态、规范包名、精确版本、锁文件位置、依赖路径、公告 ID/别名、来源、受影响范围、获取时间、快照摘要及来源提供的修复版本。没有修复版本时明确写“来源未提供”，不让模型补造。

已知受影响版本不等于已证明运行时可利用。dev/optional 等依赖类别影响风险解释，不能仅凭类别断言无风险。git/file/workspace 引用、损坏锁文件、未知格式、来源不可用或过期数据需要覆盖诊断；缓存的使用上限由配置控制并在报告中说明。

## ERR-001：空 catch 团队规范

默认关闭。使用 JS/TS AST 检测新引入的空 catch，作为团队约定提示，不直接宣称存在功能缺陷。注释说明、主动容错、清理失败等场景必须进入反例或人工裁决集。

启用后默认只进入汇总。包含 return null、日志、重新抛出等语句的 handler 不属于空块规则。复杂异常语义留给后续独立规则评估，禁止逐步扩大本规则却保留原置信度。

## 去重、抑制与反馈

同一事实可由多种检测器支持，应合并证据并保留来源，不能因工具数量增加而自动抬高置信度。跨提交匹配优先用规则、语义位置和脱敏内容指纹；行号变化不会自动生成新问题，匹配不确定时回退汇总。

抑制策略来自受信任 base 的配置或管理端。PR 中新增的抑制声明只作为待审查变更，不在本次运行自行生效。抑制记录需要范围、原因、创建者及可选到期时间；在授权审计视图中可见，不等同于删除 Finding。

反馈判断统一为 `useful / valid_not_actionable / false_positive / insufficient_evidence`，分别代表真实且有用、真实但不值得评论、误报、证据不足。是否接受风险属于独立处置字段，不能与误报混为一类；无人回复不能被当作采纳。字段定义见数据模型。反馈不能直接修改规则或训练模型，必须经过标注与回归验证。

## 规则验证

每条规则维护 positive、negative、regression 集，夹具仅用合成凭据。至少覆盖以下行为：

| 规则 | 关键用例 |
| --- | --- |
| SEC-001 | 多行私钥、占位符、真实格式的合成值、重命名/移动、脱敏日志 |
| DEP-001 | 精确版本边界、预发布版本、传递依赖、公告别名、无修复版本、未知锁格式 |
| ERR-001 | 空块、注释块、非空处理器、语法损坏、仅移动的旧代码 |
| 通用 | diff 截断、解析失败、超时、规则禁用、抑制、重复候选 |

在同一冻结输入与工具版本下验证确定性；真实 PR 另做人工标注评估。精确率和召回率分规则报告，并同时报告样本数与覆盖限制；少量单元夹具不能支撑低误报产品承诺。
