# 首版实施基线

状态：实施前设计基线，2026-10-01；尚无可运行实现。本文统一首版范围与验收编号，后续能力不作为首版交付要求。技术选型理由见[决策记录](decisions.md)。

## 1. 首版交付什么

管理员安装 GitHub App 并限定仓库后，PR 更新触发 SEC-001 检测。审查者在 Check 中看到检测范围、脱敏依据、风险说明与运行编号；授权维护者可查看证据、录入反馈、导出审计并无副作用回放。

| 范围 | 首版基线 |
| --- | --- |
| 部署 | 单组织自托管；同一代码库的 API、Worker 进程与 PostgreSQL |
| 技术栈 | TypeScript、受支持 Node.js LTS、Fastify；版本在建立工程时锁定 |
| 平台 | GitHub App；Gitee/GitLab 为后续兼容，不声称已支持 |
| 规则 | SEC-001 的列明高精度格式；成熟检测器与小型内置规则在实现任务中比较选定 |
| 语言范围 | JS/TS 仓库试点；Secret 检测可读取配置等文本，支持格式需列清；npm 漏洞分析属于 M3 |
| 默认输出 | Check 汇总；不设为 required check；行评论仅测试验证，真实仓库默认关闭 |
| 管理入口 | 受保护 CLI/API，支持 run 查看、审计导出、反馈、抑制与回放；不要求完整 Web 后台 |
| 模型 | 关闭，无模型密钥也能完成审查 |
| 源码处理 | 有界内存读取；不持久化原始源码、完整补丁或完整事件载荷 |

DEP-001、ERR-001、LLM、多模型、团队手册/RAG、自动修复、SARIF、插件市场和多平台发布不计入首版。首版只需保留不依赖平台 SDK 的领域边界，不提前实现这些模块的空壳。

## 3. 必须可演示的验收

| 编号 | 场景 | 可检查的结果 |
| --- | --- | --- |
| A01 | 同一合法 Webhook 重投；非法签名 | 合法事件只调度一次；非法请求没有任务；API 在持久化事务提交后确认接收 |
| A02 | Worker 在生成快照前崩溃 | snapshot 任务可恢复，不需要伪造 run_id 或空快照 |
| A03 | 合成密钥正例、假值、多行私钥、移动旧内容 | 有明确检测与排除依据；日志/数据库/Check 没有原始敏感值 |
| A04 | 二进制、截断 diff、超限、规则异常 | 显示覆盖缺口及原因；不输出“代码安全” |
| A05 | PR 从 A 更新到 B；目标分支推进 | 旧运行不充当当前结果；新 head 新建 Check；已发生的发布竞态可对账 |
| A06 | API 已发布但响应丢失 | 意图进入 uncertain，查询远端后再决定重试，不盲目创建第二份输出 |
| A07 | 租约失效的旧 Worker 恢复 | generation 校验拒绝旧 Worker 提交结果或新意图；外部请求竞态有审计 |
| A08 | 没有 Finding 或所有规则关闭 | 仍有汇总；前者区分完整/部分检查，后者为 not_run，不能当作干净通过 |
| A09 | 同输入确定性回放；输入缺失 | 规范化结果可比，缺失明确返回 unavailable；平台写请求与发布意图数均为零 |
| A10 | 反馈、抑制、版本改变 | 标签可审计，反馈不自动改阈值；新版本有独立运行，旧事实保留 |
| A11 | 卸载 App、仓库授权撤销、PR 内改配置 | 停止受影响访问和发布；PR 修改的安全/抑制配置不影响本次运行 |
| A12 | 同 head 两次不同配置的运行交错完成 | 只由当前指定运行更新汇总，旧运行不能覆盖新结果；远端竞态随后核对修正 |

以上为待完成验收，表格存在不表示通过。真实平台记录、故障注入记录与规则夹具分别提交；仅使用模拟 API 的测试不能替代 GitHub 集成验收。

## 4. 完成首版与证明价值分开

首版完成要求 A01–A12、可运行部署说明、权限配置、迁移/恢复步骤及兼容性清单。部署说明和运维说明随 M1 实现交付，不推迟到接入第二个平台。

进入真实试点前，明确仓库授权和数据处理方式。公开/合成夹具及技术闭环开发可先推进，不必等待收齐试点样本。试点按[评估计划](evaluation.md)检验有用发现、无用评论、核查时间与维护成本；技术验收通过不等于竞争优势成立。
